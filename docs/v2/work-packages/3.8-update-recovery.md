# Update recovery and browser connection checkpoint

- Date: 2026-10-09
- Status: implementation and focused HIL checkpoint; milestone qualification remains open
- Requirements: [web and self-update scope](3.7-device-web-and-self-update.md)
- Evidence: [recovery and coexistence trials](../evidence/web/2026-10-09-update-recovery.json)

The native release downloader now has socket capacity alongside the HTTP server,
OSC and lighting transports. The former ten-socket SDK configuration failed to
allocate its outbound connection with a browser and three other HTTP sessions.
The default is sixteen; CMake rejects stale smaller configurations. A HUZZAH32
map comparison measured 360 additional static BSS bytes, with unchanged static
data. No authentication or encryption was added.

UI 0.3.5 (code 3005, 26,475 bytes) reconnects an evicted WebSocket automatically.
Retries start at 500 ms, double to a ten-second cap and reset on successful
connection. Explicit disconnect cancels retries; obsolete sockets cannot change
the new connection or deliver stale controls. Reconnection preserves the current
view and editors. Successful web installation still intentionally refreshes the
page to load the new assets. The full bundle remains outside the application.

The native file backend disables redundant stdio buffering: callers already
provide bounded chunks and FAT/LittleFS cache their own sectors. Durability still
requires flush, fsync, close and the existing verified generation trailer. Memory
and open-file exhaustion have distinct errors. Serial diagnostics now retain the
underlying update and SD read/write failure details, separating write rejection,
busy timeout and status failure.

`blip_release_recovery_hil.py` serves a local fault catalog on the existing LAN.
It injects malformed/oversized/incorrect-identity/redirect catalogs, incorrect
artifact identity and SHA, truncated transfers, web CRC corruption, cancellation
and hardware reset during downloads. It checks retained firmware/UI/name and
storage medium. An optional real-browser observer checks connection recovery,
the single intentional asset refresh and final live control under extra HTTP
sessions. The harness waits for station readiness, records initial policy before
mutation and restores it even when a browser assertion fails. It never switches
PC Wi-Fi. An earlier observer incorrectly treated the initial Offline label of
the intentional page reload as a failure; that bounded reload is now distinguished
from a connection outage.

The public release handler and local simulator now serve devices concurrently.
A slow firmware download previously blocked catalog checks for other boards for
longer than the device's five-second HTTP timeout. The regression fixture stalls
an eight-MiB artifact reader and checks a second catalog connection independently.
This changes the separate API server only; it adds no device-side dependencies.

- HUZZAH32 and M5Dial each passed the full 128-check fault/recovery/browser
  matrix. Each also passed the 12-check native firmware upgrade to code 10.
- Ball passed native web installation on external SD (13 checks) and all three

- Ball's current external-SD fault matrix remains incomplete: the repeated trial

- All seven production profiles compile. Host tests passed 33 suites, JS passed

record. These trials do not imply seven-board milestone completion. Creators Tab

qualification and remaining application/UI integration stay open.

## Reserved worker and SD progress checkpoint

The release component now reserves its 6 KiB worker stack and task control block
at startup. Starting a download no longer needs a contiguous task allocation
after the browser, BLE and filesystem have fragmented the heap. Stop cancels and
joins the worker, parks it, and deletes it from the owner before reusing its
static task storage. The timer daemon is also quiesced before teardown.

The opt-in `BLIP_QUALIFY_RELEASE_WORKER` production qualifier exercises 30
start/stop cycles, idempotence, three queued-check cancellations, restart and
manual-update exclusion. Ball, HUZZAH32 and M5Dial each passed 220 checks on
release 21. Their task counts and settled heaps returned to their starting
values. The option is off in normal production builds. The runner is
`v2/qualification/release-worker/run_lifecycle.py`; it verifies the physical MAC,
binary board identity and generated full-flash arguments before flashing.

HTTP reads now retry the SDK's recoverable `-ESP_ERR_HTTP_EAGAIN` result while
checking cancellation. A 30-second no-progress deadline bounds a stalled peer;
the complete transfer has a separate ten-minute deadline. Positive bytes reset
only the no-progress deadline. SHA, identity, size and truncation checks still
apply. `http_read_retries` exposes actual retries. A deliberately throttled XIAO
firmware update passed in 201.6 seconds, beyond the previous two-minute deadline.
The simulator can reproduce it with `--artifact-bytes-per-second 8192`.
The API server gives a valid artifact stream a 60-second socket write timeout
and a ten-minute total bound; slow flash writes must not inherit the shorter
request-header timeout.

RAM reductions retain the 80 KiB WAMR pool, 16 KiB module limit, full copied
script queues and existing control capacities. Script text is reserved from its
declared schema rather than permanently occupying every possible string slot.
The LED, fleet network, WASM supervisor and DDP stacks were reduced from measured
headroom; qualification helpers now gate their remaining headroom. HTTP asset
reads and WebSocket receive share scratch on the same synchronous server task.
TCP MSS is 1,220 bytes with quarter-MSS oversize; C6 send/receive windows are two
MSS. When available, C6 HTTP task storage uses internal byte-accessible RTC RAM,
with a normal internal allocation fallback. DMA heap diagnostics distinguish
radio buffer pressure from total free heap.

The release-29 Ball application is 2,046,368 bytes. Its static BSS is 131,880
bytes, 2,912 bytes below release 15 despite reserving the OTA worker. The
HUZZAH32 and M5Dial BSS reductions are 2,912 and 2,896 bytes. These figures do
not include schema-dependent text or other runtime allocations. All seven
production profiles compile with the qualifier disabled.

UI 0.3.6 is 26,680 bytes and remains a separate filesystem bundle. A 1.5-second
text heartbeat keeps a live control WebSocket from becoming the HTTP server's
least-recently-used session while three extra HTTP clients are connected.
Intentional asset reloads begin with Loading and are observed separately from
connection recovery. The hardware observer permits a 15-second asset refresh
and five-second connection recovery; measured cold SD module reads take about
seven seconds.

Release 28 installed Ball web bundle 3113 and retained its loaded script, text
reservation and edited values, but the original trial remains failed: progress
reads waited behind SD validation while holding the update mutex. Release 29
publishes asset status under a separate short lock, keeping file I/O outside
status reads. A host concurrency test blocks candidate validation and checks
that the old coherent snapshot remains available, then verifies publication
after successful validation or retention after a corrupt candidate.

Detailed positive and negative trials are in
[the worker/RAM evidence](../evidence/web/2026-10-09-reserved-update-worker.json).
The current host run passes 33 suites, JavaScript passes 32 tests, and the
release-server suite passes ten tests. The seven-board milestone remains open;
Tab is absent after the reconnect, and M5StickC's previously localized UART
burst loss is still unresolved. These changes do not close the remaining

Release 29 passed 12 native website firmware checks on each of the six available

Club and Dial also passed the full 161-check WASM run, five coexistence checks,

The release-29 Ball web trial failed after 10,512 bytes with only 800 DMA bytes
free at its lowest sample. The old bundle and update policy were retained.
Release 30 caps the full BLE/WASM C6 profile's dynamic receive buffers at four,
matching its four static buffers and the SDK recommendation. It passed native

The following implementation streams JSON through the existing 1,024-byte HTTP
scratch as well. This replaces a separate 512-byte stack buffer and halves the
number of JSON payload chunks without adding static memory. Asset, JSON and
WebSocket callbacks remain serialized on the same server task. Production
qualification of that change is recorded separately in the evidence.

Release 31 passed the Ball's normal-client SD web update with a loaded script,

The six-board routerless fleet trial also passed, including election, clocks,
cues, leader loss/recovery, rejoin, direct serial control and exact restoration.
Network-task headroom ranges from 2,136 to 2,772 bytes on the reduced 6 KiB

All seven release-31 target builds pass. The first M5Dial attempt lost its

The subsequent release-31 Ball SD recovery matrix passed **145 checks** with

### Pausing background readings during updates

UI 0.3.7 pauses its three-second full schema/sensor reads while a release action
is pending or the updater reports busy. Lightweight progress, WebSocket control
and heartbeats continue. A temporary status failure retains the pause; stale
status responses cannot clear it. Readings resume after the update settles.
The filesystem factory bundle is 26,816 bytes (136 bytes larger), release 3007.
This change leaves the application binary unchanged. JavaScript tests pass
34 cases and all 33 host suites pass.

The Ball's release-31 application installed SD bundle 3118 with a loaded script,
BLE, a real browser and three extra HTTP clients. A 15-second pause before the
artifact body exercised three recoverable read timeouts. All 24 checks passed:
the browser recorded 85 paused-reading samples, no full schema reads within
the measured pause, no reconnection or JavaScript errors, and a 4.514-second
intentional refresh. Script state, controls, execution, boot, firmware, device
name and BLE survived; the update policy was restored.
The minimum sampled DMA free heap/largest block was 788/408 bytes, so this
passing transfer does not establish adequate margin for sustained load.

The evidence retains two failed trials. Serving the old UI during the first
attempt exhausted DMA headroom and retained the old bundle; installing without
a browser seeded the new UI successfully. The following three-client trial
installed bundle 3117 and passed browser continuity, but its pause after 4 KiB
elapsed while SD writes ran, so it failed the requirement to exercise a socket
read timeout. Moving the pause before the body produced the passing trial above.
Neither failed report is relabelled. The new focused concurrency result does
not qualify all automatic/manual update paths, sustained traffic or all seven
boards. Ball now retains release 31 and SD UI 3118. See
[`2026-10-09-paused-update-readings.json`](../evidence/web/2026-10-09-paused-update-readings.json).
