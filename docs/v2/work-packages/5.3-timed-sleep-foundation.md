# 5.3 Timed sleep foundation

The USB-powered Adafruit HUZZAH32 profile now exposes `blip.power.sleep` over
the V2 control registry. Its `light_sleep(duration_ms)` action accepts 1000 to
30000 ms, arms an ESP-IDF timer wake source, and returns to the running firmware
without a reboot. The action requires the Wi-Fi radio and pixel output to be
disabled before it can start. A worker waits for the serial acknowledgement and
UART drain before entering sleep; it checks those preconditions again at entry.
The registry reports state, completed cycles, wake cause bitmask, ESP-IDF error,
and the last measured sleep interval.

`v2/tools/control/blip_sleep_hil.py` saves both `enabled` settings, disables
them, requests sleep over serial, waits for the timer, checks the wake result,
and restores the saved settings. The HUZZAH32 run and all six firmware build
results are recorded in
`docs/v2/evidence/board-bringup/2026-10-01-huzzah32-timed-sleep.json`.

This is a controlled qualification path. The other five profiles have no sleep
action yet. Creators Ball V2, Creators Tab, and M5Dial have board power latches;
their hold and wake behavior must be verified before deep sleep is enabled.
The Ball's GPIO19 button is outside the ESP32-C6 RTC deep-sleep GPIO set.
The ESP-IDF [sleep API](https://docs.espressif.com/projects/esp-idf/en/v6.0/esp32/api-reference/system/sleep_modes.html)
provides the timer wake and light-sleep calls used here. Automatic idle sleep,
power-management locks, deep sleep, coordinated live radio suspension, and
measured idle/sleep current on each board remain open for milestone 5.3.
