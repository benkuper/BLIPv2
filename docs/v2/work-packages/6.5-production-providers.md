## Composition and APIs

The worker binds the immutable component catalog after composition and before
registry validation. Each provider advertises its exact import namespace as a
lifecycle service; the worker derives required services from the catalog. Its
descriptor address stays stable. Runtime configuration and teardown run on the
worker. Reverse dependency shutdown joins it before retiring provider resources;
failed consumer shutdown retains transitive providers and permits retry.

`blip.output.strip0.v1` exposes `fill`, `clear`, `frames` and `pending`. Fill
accepts five unsigned linear 16-bit RGBW/alpha channels. Four fixed queue slots
reject overflow. The render task consumes/coalesces admitted commands into a
uniform script layer below the system layer and above stream input. Its nominal
queue poll is 10 ms; driver service and higher-priority work can extend latency.
Admission does not wake the render task. Base settings remain unchanged. RGB
hardware folds white into RGB; RGBW preserves white. Blackout clears script work.
The layer persists across module unload until clear/blackout/owner stop.

`blip.fleet.v1` exposes clock readiness, time, leader and scheduled signed-i32
writes/actions without arguments. IDs use checked `(offset, byte_length)` copies
into fixed 64-byte buffers, ASCII ID validation and embedded NUL rejection.
Encoded cues own their data; no guest pointer survives admission. Delays are
100..60000 ms. Self-reconfiguration is refused. Permanent admission gates protect
callbacks against stop; engine contention is an immediate explicit failure.

Without WASM, these components have no provider inheritance or interpreter
imports/dependency. Existing V2 settings and hardware formats remain.

## Timing and reservations

The bridge enforces the declared 2 ms maximum against scheduled task execution
time, including interrupt service and bounded meter overhead. ESP-IDF 64-bit ESP
timer runtime statistics and yields flush unfinished task accounting. Other
tasks and blocked time are excluded. The whole guest call still has an absolute
wall-clock deadline enforced by its supervisor. Trusted providers must remain
bounded and nonblocking; post-return checks cannot forcibly preempt native code
or roll back effects. Both wall/task last and maximum times are public parameters.

Ball diagnosis measured three malformed-ID callbacks at 2.2..3.1 ms wall time
but 287..317 us task time. The former wall-time enforcement replaced their proper
validation errors with budget failures. The final 500-validation trial preserves
all error/result contracts, including two callbacks above 2 ms wall time.

The owner test also reproduced script restart fragmentation: the engine pool
could be reallocated, but the largest remaining heap block was 14,336 bytes,
insufficient for the 16 KiB module buffer. Routine stop/suspend now retains the
fixed 96 KiB buffers. `buffer_reserved` reports this separately from a stopped
engine's zero `pool_reserved`. Cold startup failure rolls back new reservations;
warm failure retains prior reservations. Permanent retirement releases buffers
only after stop/join. Live release is refused, and destruction requires quiescence.

Suspend stops these three components and rejects provider admission. Their
descriptors explicitly do not support automatic resume; controlled restart calls
start after quiescence. The render/fleet start paths refuse still-active workers.

## Qualification

All 24 host suites pass, including 10 core cases and 13 capability cases.
Production HIL completed **2,706 checks** across five profiles, with 100
reload/unload cycles per profile and constant idle registration pool use.

| Profile | Checks | Maximum wall time | Maximum task time | Script worker headroom |
| --- | ---: | ---: | ---: | ---: |
| ball | 1,335 | 2,247 us | 312 us | 2,696 B |
| club | 335 | 816 us | 493 us | 2,732 B |
| xiao | 366 | 4,061 us | 386 us | 2,744 B |
| huzzah32 | 335 | 4,433 us | 474 us | 2,720 B |
| m5dial | 335 | 954 us | 389 us | 2,492 B |

Pool peaks are 78,000..78,008 bytes within the 80 KiB total engine/linear budget.
The helper restores LED settings and leaves validated test firmware installed.
Physical color, current and output timing are not established by frame counts.

The XIAO/HUZZAH32 pair elected and synchronized on a private routerless ESP-NOW
fleet. Both guest clocks were ready and monotonic. Guest-created brightness and
blackout cues executed once on each node after the origin's identifier bytes
were overwritten and its module unloaded. Radio state confirmed no router
association or setup AP. Original fleet/LED settings were restored. The PC Wi-Fi
connection was unchanged throughout testing.

An opt-in image exercised actual SPI Ball and RMT HUZZAH32 owner lifecycle:
**61 checks each**, four owner suspend/restart cycles after joining the actual
script worker, stopped-owner refusal with untouched results, retained reservation
and worker restart after owners. Callbacks run on a separate exclusive worker.
It does not inject failed live provider teardown or prove multi-core render task
reuse under stress. Qualification code is absent from all production images.

The native import qualifier was renewed on ESP32, S3 and C6: **2,613 checks**, a
CPU-bound injected task-time overrun, active cooperative cancellation, 100 reloads
and 20 engine restarts per board. The actual production worker qualifier passed
**3,976 checks**, including six/seven allocation/task failure stages, backend
failure, active and queued cancellation, supervisor deadlines and 20 restarts
per board with flat warmed heap/task counts. Cold-fault tests explicitly retire
the reservation, retaining coverage of real startup allocations.

Seven complete production profiles build and fit. Compared with the native
bridge checkpoint, app size grows 8,896..13,232 bytes and linked static RAM grows
1,328..1,592 bytes. The fixed 96 KiB script buffers are startup heap reservations;
the per-task runtime-statistics overhead also consumes SDK task memory. A C6
fleet/ESP-NOW build with WASM disabled builds with no WAMR symbols.

M5Dial uses primary native USB console and a matching bootloader. A fresh S3
configuration selects it through `sdkconfig.esp32s3.defaults`. This Windows test
board needed esptool's default stub-assisted `run` after flashing; no-stub run was
insufficient. Readiness is verified over serial. Console and binary replies share
the driver. Installer/reset behavior needs separate qualification.
