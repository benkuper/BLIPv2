- Date: 2026-10-08
- Status: publication/typed action slice qualified; complete 6.6 pending
- Contract: [ADR-0017](../adr/0017-wasm-live-controls-upload-storage.md)
- Evidence: [production trials](../evidence/wasm/2026-10-08-production-live-controls.json)

The production worker now owns the 11,792-byte script store and 664-byte message
scratch outside its native stack. It prepares declarations before engine load,
validates callbacks/string arena, and publishes live registry controls. Parameters
use copied owned values. Script actions join the existing ordered request queue
and completion ring with captured budgets, full-width i64/f64 bits and checked
guest string copies. Accepted unload/replacement closes action admission.
Fault/unload/stop retires schema; teardown includes registry lease quiescence.

The pool remains bounded at 80 KiB and is reserved before service startup.
Upload storage is now worker-owned and sized to the accepted module, bounded
at 16 KiB, after unloading/detaching the previous buffer. Routine stop retains
buffers; permanent retirement releases them after quiescence. Memory descriptors
report the maximum; diagnostics report the actual reservation. ADR-0017 explains
the failed Ball HTTP allocation and S3 boot fragmentation trials preserved in
the evidence. Earlier standalone results remain historical evidence.

All **28 host suites**, foundation/bootstrap/resource validators, seven production
builds and the WASM-disabled build pass. The standalone runner's declared case
count was updated from six to seven for the new checked action conversion test;
this checkpoint does not claim a rerun of that independent qualifier.
