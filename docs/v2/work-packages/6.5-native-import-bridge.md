## Implemented

The replaceable runtime API optionally configures a component catalog before
initialization. WAMR registers exact versioned namespaces using numeric raw
signatures and stable per-function attachments. Copied names/signatures, mutable
symbols and registration nodes live in the existing fixed engine pool. No
engine header enters the core/provider API, no SDK heap fallback is added, and
absent/empty catalogs allocate no registration table.

A portable reader checks original module names before engine interning: exact
allowlisted namespaces/functions, UTF-8, no embedded NUL or underscore aliases,
function imports only, maximum 32 imports, no start section or automatic
constructors. WAMR then validates/link-checks the binary and the adapter checks
each exact numeric signature before instantiation. Module loading executes no
provider callbacks. Callback memory is always the current active instance.

Fixed scratch preserves raw scalar bits and caller output on failure. Native
availability, cancellation, malformed results, recursion and callback overruns
fault the script with stable codes and bounded namespace/function diagnostics.
Snapshots count native calls/failures and elapsed time. Registration failure,
normal unload/shutdown and engine restart release all owned metadata and global
engine ownership.

Native callbacks are trusted bounded code. Their elapsed-time declaration is
checked after return; fuel does not preempt a native callback. Cancellation is
cooperative and cannot undo completed provider effects. Real provider code must
use immediate bounded queries or queue admission and validate inputs before
effects.

## Qualification

The two new host cases first failed with unresolved import-policy symbols.
They cover exact versions/signatures, original name bytes, embedded NUL aliases,
truncation and malformed sections. All **24 host suites passed**; the capability
suite now has 12 cases.

Actual guest imports ran on HUZZAH32 ESP32, M5Dial S3 and XIAO C6. Each completed
871 checks, for **2,613 checks with zero failures**. Eleven functions from two
independent synthetic owners cover numeric bits, eight mixed/wide arguments,
void returns, checked Unicode text, exact writes without terminators and
unavailable/suspended owners. Fifteen negative fixtures reject names, signatures,
non-function imports, constructors and excess imports without executing code.
A memoryless fixture accepts 32 imported function slots.

Fuel exhaustion, callback status failure, malformed results, recursion, a
deliberate 10 ms callback overrun and main-task `request_cancel` during an active
cooperative callback all fault as expected. The initial XIAO trial exposed a
race in the qualifier's cancellation acknowledgement flag; publication now
precedes the cancellation request, and the corrected trial passed. This was a
test synchronization issue; no cancellation failure was inferred from it.

Each board completes 100 reload/copy/unload cycles with constant warmed SDK
heap, then 20 engine reinitializations. Injected failures at registration one
and two clean up the entire engine and permit retry. Heap integrity passes.
No production driver or radio tasks run in this isolated qualifier.

the PC network was unchanged. M5StickC was absent from serial inventory.

## Compatibility and cost

Seven production profiles compile with WASM, ESP-NOW/fleet, Art-Net and DDP;
Ball retains BLE. Every image fits its existing partition. The bridge and
explicit import policy are linked; qualifier wrappers are absent. These images
were built, not flashed in this trial.

guest-import rejection without a data migration.
