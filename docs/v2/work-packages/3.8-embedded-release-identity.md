# Work package 3.8: Embedded firmware identity and release packaging

- Date: 2026-10-09
- Status: image identity/packaging qualified; native self-updates open
- Contract: [ADR-0019](../adr/0019-device-release-catalog.md)
- Evidence: [seven images and three boards](../evidence/ota/2026-10-09-release-image.json)

Firmware now embeds its board, target, layout, profile, configured flash size,
feature mask, API and monotonic release code directly after the native app
descriptor. Prefix validation compares the actual binary metadata and native
project/version against a selected release. Build configuration rejects invalid
release codes/profile names and incompatible partition filenames. Existing
local OTA and native boot confirmation behavior are retained.

The OTA component publishes eight immutable identity/version parameters over
the existing control and OSCQuery services, making them available to Advanced.
The local packaging CLI reads actual firmware metadata and the verified web
bundle, calculates size/SHA-256, creates immutable digest-named files and
atomically publishes the index after verifying the copied bytes. It rejects
same-code changes and downgrades, and retains the independent web release during
firmware-only publication. The user selected a separate API server; deployment
instructions for the Python handler and packaging tool are provided together.

All **30 host suites**, **five server tests** and **four packaging tests** pass.
All seven production profiles plus WASM-disabled compile. The compiled C++
prefix validator checks all seven actual application binaries and rejects wrong
board/layout/profile/flash/features/code/version: **56 binary checks**. Packaging
all seven generated images produces one local multi-device catalog; its hash is
recorded. Native linker placement is checked from the actual binary bytes.

The Ball C6, HUZZAH32 ESP32 and M5Dial S3 were flashed with their generated app
arguments. Each passes 16 serial/OSCQuery identity checks and 99 production
script-control regressions with 20 replacement cycles: **48 identity checks**
and **297 regression checks**. Exact image, flash log, source snapshot, checker,
report and test log hashes are bound in the evidence. Ball retained its 8 MB
layout; S3 application readiness was verified over serial. PC Wi-Fi was never
changed, and the validated images remain installed.

Static RAM increases by **64 B** per profile; application growth is
1,760–1,840 B. Warmed script-control heap is 25,496–25,504 B on Ball,
32,800–32,820 B on HUZZAH32 and 34,920 B on S3. Worker stack headroom is
4,980/4,928/4,712 B respectively. These are short regression trials, not soak
qualification. Other four boards are compile-only for this checkpoint.

The descriptor validator and packaging system do not themselves perform a
device HTTPS request or install a remote artifact. Native HTTPS ownership and
memory coordination, clock/certificate verification, the update center,
automatic policy, live API deployment and adverse-path update HIL remain open.
