# Work package 2.5: Common envelope and Serial/USB transport

- **Status:** implementation, host checks, three-target builds, normal-mode hardware
  qualification, recovery-mode qualification, and V1 migration qualification complete.
- **Depends on:** ADR-0001, ADR-0004, ADR-0006, work packages 1.2, 1.3, and 2.4.
- **Scope:** the versioned common envelope, registry-validated control dispatch,
  COBS-framed UART/USB transport, a bounded V1 parser adapter, and a host CLI.

## Public behavior

V2 uses one binary envelope for transports. Serial carries that envelope with
COBS encoding and a zero-byte delimiter. Replies also emit a leading zero sync
delimiter so a host can discard buffered console text before the binary frame.
ESP32 uses UART0; ESP32-S3 and ESP32-C6
use their native USB Serial/JTAG controller. The transport owns fixed request,
decode, payload, response, and task-stack buffers. It does not parse or allocate
unbounded input.

V1's line protocol is not silently mixed into the binary stream. A bounded,
opt-in adapter preserves the documented `yo` discovery request, dotted command
lines, scalar inference, discovery response shape, and the V1 negative-number
quirk for compatibility endpoints that explicitly select it. V1 OSC paths are
unchanged by this package; OSC is implemented in 2.7.

## Envelope v1

All multibyte values use little-endian order. CRC is IEEE CRC-32 over the exact
header and payload while treating the CRC field itself as zero.

| Offset | Size | Field |
| ---: | ---: | --- |
| 0 | 4 | magic bytes `BLIP` |
| 4 | 1 | format version (`1`) |
| 5 | 1 | header size (`24`) |
| 6 | 1 | kind: request, response, event, or error |
| 7 | 1 | flags; zero in version 1 |
| 8 | 4 | request ID |
| 12 | 2 | payload type |
| 14 | 2 | payload byte count |
| 16 | 4 | reserved; zero |
| 20 | 4 | CRC-32 |
| 24 | 0-512 | payload |

The supported payload identifiers reserve control, descriptor, diagnostics,
and provisioning from the first version. This package implements control.
Unknown versions, enum values, flags, reserved bytes, sizes, and CRCs fail
closed. The largest envelope is 536 bytes and the largest delimited serial frame
is 540 bytes.

## Control payload v1

The 12-byte control header contains version, operation, value count, structured
error domain/code, and bounded byte lengths for component ID, control ID, and
error detail. It is followed by those strings and up to four typed scalars.
Each scalar has a type, a zero reserved byte, a 16-bit byte count, and data.
Boolean is one byte; integer and finite number are eight bytes; UTF-8 strings
are at most 128 bytes.

`RegistryControlService` dispatches only to a running registered component. It
checks the immutable descriptor before invoking component code: parameter
existence, read/write access, scalar type and numeric bounds, action existence,
argument count, and argument types. Failures return the same request ID in a
structured error envelope. The transport is present in normal and safe-mode
registries but does not accept control until registry startup, legacy import,
and boot confirmation have succeeded.

Diagnostics exposes live `log_level`, `clear_safe_mode`, and `erase_coredump`
controls. The normal bootstrap exposes the non-persisted bounded `probe_value`
parameter and `reset_probe` action solely as a transport acceptance probe.

## Host utility

[`blip_serial_control.py`](../../../v2/tools/control/blip_serial_control.py)
implements the exact envelope, CRC, typed-control, and COBS contracts with the
Python standard library plus pyserial. It supports `get`, `set`, and `action`,
prints deterministic JSON, returns a nonzero status for protocol/device errors,
preconfigures DTR/RTS to avoid bridge-induced resets, and waits for a quiet boot
log interval before its first frame. Its codec self-test is a CTest entry and
does not require pyserial or hardware.

## Memory and execution policy

The serial component owns a static 4 KiB FreeRTOS stack and one static task at
priority 5. Its complete object occupies 6,960 bytes of BSS on ESP32/S3 and
6,944 bytes on C6, below its 8 KiB descriptor budget. The linked transport
library contributes 6,420 bytes on ESP32, 6,394 bytes on S3, and 7,388 bytes on
C6. Codec and dispatcher paths use caller-owned spans and fixed arrays. Frame,
rejection, and overflow counters saturate instead of wrapping.

## Rollback

Rollback is an application replacement for devices already using the V2
partition table. The common envelope and bootstrap probe have no persisted
state. Stopping the registry quiesces and removes the transport task and deletes
only a driver it installed itself. The Creator Ball's byte-for-byte 8 MiB V1
image can restore its original bootloader, OTA layout, apps, NVS, SPIFFS, and
coredump if V1 recovery is required.
