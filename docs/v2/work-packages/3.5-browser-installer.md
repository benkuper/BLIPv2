# Work package 3.5: browser factory installer

- **Status:** implemented; physical browser-dialog qualification in progress.
- **Depends on:** work packages 3.2 and 3.3.
- **Scope:** complete factory images, ESP Web Tools/esptool-js manifest, ESP
  Launchpad publication config, post-flash provisioning instructions, and
  browser-driven A/B application updates.

Every target build produces a deterministic empty 640 KiB LittleFS image. The
release builder merges bootloader, partition table, erased OTA selection state,
the initial application, and that filesystem into one 4 MiB image per chip.
The initialized filesystem is mandatory: app-only flashing is insufficient on
a blank device and correctly fails closed on corrupt nonblank media.

`v2/installer/build_browser_installer.py` validates target identity and the
qualified 4 MiB DIO layout, produces SHA-256 provenance for every source and
merged artifact, and writes both manifest formats. ESP Web Tools selects the
chip family automatically. The Launchpad config points all three families at
the same merged artifacts.

The opt-in C6 BLE images now have separate board-specific factory packages.
Creators Ball V2 uses 8 MiB flash with storage at `0x620000`; XIAO C6 uses
4 MiB flash with storage at `0x360000`. The builder checks the board build and
partition profile before merging. Both have the same C6 chip family, so the
installer page requires the correct board package to be selected explicitly.

The installed device serves the schema-driven control UI from its embedded
factory bundle. The initial flow is: join `BLIP-xxxxxx`, open
`http://192.168.4.1`, invoke the generated Wi-Fi provisioning control, reconnect
to the LAN, and open the device there. Improv Serial is not implemented or
claimed. Later application images can be validated and uploaded from the
browser maintenance panel; project/version metadata and SHA-256 are derived in
the browser, while the user selects the matching target.

## Acceptance evidence

- All three build directories emit `storage.bin` and merged images below 4 MiB.
- Manifest validation checks the chip-family mapping, offsets, target identity,
  complete source hashes, and matching version.
- Web tests cover application-descriptor parsing, digest generation, headers,
  invalid images/targets, and update rejection.
- A blank physical target still requires a user-confirmed Web Serial install
  run from a secure hosted origin before this work package can be marked fully
  qualified.

The final Milestone 3 builds were merged again after the resource-inspector and
XIAO antenna changes. The current artifact hashes, 21 browser tests, 15 host
suites, and the unavailable interactive-browser probe are recorded in
[`2026-08-15-browser-installer-m36.json`](../evidence/browser-installer/2026-08-15-browser-installer-m36.json).
The earlier command-line factory flash remains useful physical evidence for the
merged layout, but it is not substituted for the required Web Serial dialog.
The [BLE C6 package evidence](../evidence/browser-installer/2026-10-01-ble-c6-packages.json)
records the new merged-image sizes and hashes. Their Web Serial install and
