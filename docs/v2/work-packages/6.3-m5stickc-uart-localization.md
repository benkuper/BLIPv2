# Work package 6.3 follow-up: M5StickC UART loss localization

- Date: 2026-10-07
- Result: missing reply bytes localized beyond the UART input boundary; serial burst gate remains open
- Evidence: [UART localization](../evidence/wasm/2026-10-07-m5stickc-uart-localization.json), [earlier damaged reply](../evidence/wasm/2026-10-07-m5stickc-serial-burst.json)

## Method

The focused production test records the exact bytes returned by pyserial before
the BLIP client's framing/pending-response processing. An independent parser
finds the same malformed candidates in those raw reads. A warmed baseline burst
received twelve of thirteen replies; one was missing the `s` in `blip.wasm`.
Offline insertion of that byte validates the original envelope CRC. This rules
out the BLIP frame parser dropping that byte after the read.

The opt-in diagnostic build wraps `uart_write_bytes` without changing production
component sources or vendor code. Immediately before driver entry, it decodes
the actual outgoing COBS frame, checks its envelope CRC and stores request ID,
encoded length, frame CRC32 and driver return count in a fixed 32-entry ring.
It emits no trace logs during the burst. A later ordinary bootstrap probe dumps
the saved records. The wrapper adds CPU/stack use, so reproduction under this
instrumentation is explicitly required before claiming localization.

The trace image uses the M5StickC production board selection with WASM,
ESP-NOW/fleet, Art-Net and DDP enabled. The verified MAC is
`94:b9:7e:8b:b7:84`. Its app is **1,268,672 bytes**, **2,640 bytes** above the
untraced production checkpoint. The 32 records and sequence counter add
772 bytes of static storage; temporary decode/format buffers use the existing
serial task stack. The hook exists only in the explicitly selected diagnostic
build directory.

## Observations

| Instrumented trial | Replies received / requested | Malformed binary candidates | Matched single-byte losses |
| --- | ---: | ---: | ---: |
| 1 | 9 / 13 | 4 | 2 |
| 2 | 12 / 13 | 1 | 1 |
| 3 | 13 / 13 | 0 | 0 |

All thirty-nine burst replies were valid immediately before driver entry and
had full driver return counts. Three damaged host candidates have a unique
single-byte reconstruction that also matches the saved pre-driver frame CRC:

| Trial / request ID | Pre-driver encoded bytes | Driver accepted bytes (including delimiters) | Missing byte |
| --- | ---: | ---: | --- |
| 1 / 18 | 63 | 65 | `0x01` |
| 1 / 22 | 63 | 65 | `0x6c` (`l`) |
| 2 / 59 | 68 | 70 | `0x08` (initial COBS code) |

The other two malformed binary candidates are shorter by two bytes and are not
reconstructed by the single-byte search. Trial 1 also records one expected
plaintext Wi-Fi startup candidate between delimiters. Such console text fails
COBS decoding and is included in the raw invalid-candidate list; it is not a
damaged binary reply. Missing bytes also appear in trace dump text, but all
thirteen burst trace records per trial remain available for correlation.

Reconstruction is diagnostic inference, checked against the original envelope
CRC and the pre-driver frame CRC. The control client never accepts repaired
bytes. The collector validates both build artifacts, current production source
snapshot, trace source hashes, flashed identity, complete burst trace coverage,
full driver counts and matched deletions before saving the evidence.

## Outcome and remaining work

The observed loss happens after the encoded frame reaches the UART driver input
boundary. A successful driver return establishes admission, not physical
delivery. The UART driver/ISR, electrical UART path, USB bridge, Windows serial
driver and pyserial remain possible locations; this trial does not identify
which one loses the bytes. The board remains responsive after all trials and
the guest is unloaded. The PC network is unchanged and the diagnostic testing
firmware remains installed; no previous image was restored.

See the [diagnostic README](../../../v2/qualification/serial-burst/README.md) for
reproduction and the explicit CMake hook. This evidence does not qualify queue
overload: twelve UART requests can outlast the 50 ms guest deadline and allow
the worker to advance during admission. The two omitted M5StickC production
burst checks and full Gate D remain open.
