# Work package 1.2: registry and lifecycle

## Scope

`blip_core` provides a fixed-capacity component registry and the lifecycle from
construction through validation, start, suspend, resume, and stop. Validation
closes registration, rejects invalid or duplicate identities, resolves service
dependencies, and produces a deterministic topological order with lexical tie
breaking.

Startup is permitted once. A partial startup failure stops already-started
components in reverse order and preserves both the primary failure and bounded
cleanup errors. Stop requires component callbacks to report quiescence.

## Acceptance evidence

Host tests cover stable ordering, duplicate component IDs, missing services,
dependency cycles, partial-start rollback, cleanup failures, idempotent
suspend/resume/stop, callback quiescence, and rejection of a repeated start.
The same implementation is compiled into the ESP32, ESP32-S3, and ESP32-C6
firmware images.

## Compatibility, rollback, and migration

This package exposes no V1 protocol or persistence surface. Removing
`blip_core` from the V2 application composition rolls it back; no data migration
is required.
