## Changes

Components can expose a `DynamicSchemaSource` independently of a WASM engine.
Its move-only lease pins one immutable generation and releases it exactly once.
An inactive source produces an empty successful lease; busy sources reject
admission immediately. Metadata remains owned by the component throughout every
lease. At most 16 controls can be leased. Owners must validate metadata, reject
collisions with existing controls, implement reader-safe publication/retirement,
and use stable diagnostic text. The interface itself implements no owner lock.

The dispatcher projects existing parameter/action descriptors while holding a
lease. It validates access, arguments, types and numeric bounds before invoking
the owner's dynamic operation. Hooks receive the captured generation; explicit
requests for an older generation fail before the hook. A retiring owner must
recheck the token at admission and tag all queued payloads. A request with token
zero resolves the current generation. Existing external wire protocols do not
yet carry explicit generation tokens, so an old external packet without one
cannot be distinguished from a new request.

`ControlResponse` owns a fixed 512-byte string arena, with deep copies and moves
that rebase owned views. Dynamic string hooks must write to the caller's arena;
returning borrowed owner/guest text is rejected. Static results are copied before
the dispatcher returns. This does not add synchronization to static owners.
Oversized strings/results fail explicitly. Clearing a response fills existing
storage directly, avoiding a full response temporary on the dispatch stack.

OSCQuery emits leased parameters/actions/events through its existing descriptor
writers and adds `BLIP_SCHEMA_GENERATION` to the component container. The lease
remains held until that container finishes serialization. String responses stay
alive throughout value serialization. Scratch for control projections and path
matching is in separate calls, rather than repeated in recursive frames. The
embedded compiler is explicitly prevented from inlining those helpers into the
recursive frame. Source contention/projection failure aborts serialization;
the existing tree writer reports its generic serialization error.

OSC routing captures the lease token and uses the same dispatcher. Each UDP or
WebSocket endpoint owns 512 bytes for string feedback, valid until its next
call. The existing public paths remain unchanged. Existing OSC/browser numeric
limits remain: full i64 declarations still need lossless external encoding.

## Qualification

The tests first failed because dynamic dispatch was unimplemented. All **26 host
suites** now pass. The six shared cases cover lease moves/release, typed bounded
dispatch, stale-token refusal before action admission, access checks, wrong
result types/counts, rejected borrowed strings, owned response copy/move and
overlapping source slices, leased OSCQuery serialization and OSC feedback.

The exact generated C++ JSON is parsed independently and passed to the unchanged
generic web model. It produces a number editor, text editor, typed action and
read-only event, with the correct labels, bounds, unit, values and fields. All
21 web tests pass. This is model integration, not browser automation or evidence
of guest-defined controls running on a device.

The native qualifier compiles the same portable sources and six cases against
ESP-IDF v6.0.2. One warm run and 20 repeats give **126 case passes per target**:

| Board | Target | Warm internal heap throughout repeat | Qualifier stack headroom |
| --- | --- | ---: | ---: |
| XIAO | C6 | 453,332 B | 14,596 B |
| HUZZAH32 | ESP32 | 274,412 B | 14,388 B |
| M5Dial | S3 | 374,284 B | 14,236 B |

The allocating test fixtures use a 20 KiB qualification stack. They are a
single-threaded surrogate owner, not the production worker or a concurrency
test. `ControlResponse` is 776 B and each OSC endpoint is 688 B on these targets.
The final C6 recursive tree frame is 256 B, down from 704 B before the scratch
split; the representative dispatcher frame drops from 864 B to 96 B with direct
clearing. Individual compiler frames do not prove complete call-chain bounds.

Normal production images were also flashed on one board per family. Each passed
18 checks for full HTTP trees, protected write-only password metadata and owned
string replies over serial, UDP and WebSocket. Each also passed 95 existing
LED/fleet guest-provider checks, including 20 reloads and preserved invalid-input
errors. Their measured minimum margins after the transport checks are:

| Board | HTTP stack headroom | UDP stack headroom | WASM worker stack headroom |
| --- | ---: | ---: | ---: |
| Creators Ball | 2,844 B | 1,856 B | 2,828 B |
| Creators Club | 2,500 B | 1,632 B | 2,708 B |
| M5Dial | 2,332 B | 1,408 B | 2,508 B |

The first production Ball query exposed a 728 B HTTP margin. After reducing
recursive scratch, the final transport trial passes the 1 KiB minimum gate.
These trials use existing static controls and the current full registry tree,
not a maximum-size live script schema. They do not measure physical LED color,
waveform correctness or long-term heap behavior.
