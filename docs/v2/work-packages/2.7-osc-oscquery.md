# Work package 2.7: OSC UDP and OSCQuery discovery

- **Status:** implementation, host checks, reproducible three-target builds, and
  physical ESP32 UDP/HTTP/WebSocket qualification complete.
- **Depends on:** ADR-0001, ADR-0003, ADR-0004, ADR-0006, work packages 1.2, 1.3,
  1.4, 2.5, and 2.6.
- **Scope:** bounded OSC codec and UDP endpoint, registry-generated OSCQuery HTTP
  and WebSocket discovery, V1 path aliases, and shared HTTP-server integration.

## Public behavior

`blip.oscquery` provides `transport.osc` and `discovery.oscquery`, requires
`control.dispatch` and `network.http`, and listens for UDP OSC on port 9000. The
device ID is the uppercase station MAC with colon separators. `/yo [host]` returns
`/wassup <local-ip> <id> <type> <name> <version>` and `/ping [host]` returns
`/pong <id>`. Other messages route `/<component-path>/<control>` through the common
registry `ControlService`; the OSC adapter contains no component-specific handler.

UDP parameter and action feedback uses the request address and prefixes the device
ID. Binary WebSocket feedback uses the same address but omits that prefix. The
liveness reply retains its V1 device-ID argument on both transports. Text WebSocket
frames receive `{"ok":true,"kind":"debug"}`; malformed binary OSC receives a
bounded JSON error.

The codec accepts one message up to 1,024 bytes, addresses up to 128 bytes, strings
up to 256 bytes, and eight useful control arguments. It supports OSC boolean `T/F`,
int32 `i`, float32 `f`, string `s`, RGBA `r`, MIDI `m`, and timetag `t`. Addresses,
UTF-8 strings, four-byte padding, finite numeric values, exact packet length, and
output capacity are validated. Bundles, blobs, arrays, unsupported tags, malformed
padding, truncation, and trailing bytes fail closed. The fixed packet, response,
value, address, and task buffers make all codec and routing limits explicit.

## OSCQuery and registry ownership

The Wi-Fi component owns a single port-80 server and delegates the root handler to
this component. On a blank device, plain `GET /` still serves the setup form;
`GET /?HOST_INFO`, `GET /?config=1`, `GET /?config=0`, and WebSocket upgrades serve
OSCQuery. On a station connection, plain `GET /` also serves the complete tree.
Responses use streamed chunks rather than materializing the registry tree in RAM.

Host info preserves the uppercase OSCQuery keys and advertises UDP port 9000. The
tree is generated solely from `RegistryView`: component metadata determines legacy
paths, descriptors determine controls and types, and `ControlService` supplies live
values. Containers have access 0, read-only leaves access 1, and writable parameters
and actions access 3. `config=0` omits parameters marked as persisted configuration
but keeps status, actions, events, and dynamic controls.

Descriptors can declare a typed `LegacyParameterAlias` that binds a public legacy
name to one canonical parameter. Optional enum tables convert canonical values to
legacy string labels in both OSC routing and OSCQuery `VALUE`/`RANGE`. Registry
validation rejects missing canonical parameters, duplicate or colliding aliases,
bad types, invalid names, and malformed enum maps. Wi-Fi declares these mappings:

| Canonical parameter | V1 OSC/OSCQuery name | Legacy representation |
| --- | --- | --- |
| `mode` | `mode` | `Wifi`, `AP`, `Wifi+AP` |
| `password` | `pass` | string, write-only |
| `manual_ip` | `manualIP` | string |
| `manual_gateway` | `manualGateway` | string |
| `channel_scan` | `channelScanMode` | boolean |
| `tx_power` | `txPower` | `15dBm`, `17dBm`, `19.5dBm`, `20.5dBm` |
| `protocol` | `wifiProtocol` | `11B`, `11BG`, `11BGN`, `AX` |

The password path is discoverable for compatibility but never contains `VALUE` and
cannot be read over OSC. This is an intentional security correction to the captured
V1 tree. `/wifi/signal` remains read-only because received signal is observed state,
not a meaningful writable setting.

## Security, memory, and tasks

OSC UDP, OSCQuery HTTP, and WebSocket control are unauthenticated compatibility
endpoints without transport encryption. They are suitable only on a trusted local
LAN. They must not be port-forwarded or exposed to an untrusted network; a production
deployment requiring remote access needs authentication, authorization, replay
protection, and TLS at an application gateway or in a later versioned endpoint.
CORS remains open to match LAN discovery clients.

The component object is statically bounded below 16 KiB and owns a static 6 KiB,
priority-4 UDP task stack. The shared HTTP server stack was raised from 4 KiB to
8 KiB after measuring the streamed tree callback. Packet counters saturate and stop
waits for both the UDP task and active HTTP callbacks to quiesce. Physical stress on
ESP32 left 2,800 bytes of UDP-task stack headroom and 2,224 bytes of HTTP-task
headroom. The final cold boot reported 148,584 bytes free heap, a 110,592-byte
largest block, 4,816 bytes main-task stack headroom, and no retained coredump.

## Verification

RTTI disabled. Five OSC/OSCQuery cases re-encode the pinned V1 binary datagrams,
round-trip every supported value type, reject corrupt packets, route reads/writes,
actions, discovery, typed aliases, and enum labels through a synthetic registry,
compare registry-derived tree semantics, verify configuration filtering, and check

## Hardware evidence

COM6 identified the existing ESP32-PICO-D4 revision 1 with MAC
`50:02:91:9c:36:ac`. The final app-only flash preserved the 2 MiB compatibility
partition table and blank NVS state. On its `BLIP-9C36AC` hotspot, the setup page
remained reachable while OSCQuery returned host info, the complete 4,835-byte live
tree, and a filtered tree. The tree contained the exact V1 Wi-Fi aliases and string
enum values, omitted canonical underscored spellings, and exposed `pass` without a
value.

UDP `/yo` and `/wifi/mode` returned the expected identity and `Wifi` value. A binary
WebSocket write changed the volatile bootstrap probe and returned feedback without a
device-ID prefix; `/ping` and a text debug frame also passed. A subsequent stress run
performed 30 UDP reads, 10 full HTTP tree streams, and 10 WebSocket writes. The board
then cold-booted ready in 835 ms with `coredump=absent`. The workstation reconnected to
`Archi-Wifi` after each isolated hotspot test and the temporary BLIP profile was
deleted.

## Rollback

This package changes no partition table or persisted record schema. Application-only
rollback to 2.6 is safe: flash the prior application into the existing factory slot.
The older image ignores the added descriptor aliases and leaves NVS, LittleFS, and
the retained V1 source blob unchanged. OSC/OSCQuery endpoints simply disappear when
the 2.6 application boots.
