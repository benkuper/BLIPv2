# Work package 6.5: Component-owned provider contract

- Date: 2026-10-08
- Result: portable contract qualified; guest-to-native bridge remains pending

- Evidence: [provider contract](../evidence/wasm/2026-10-08-component-provider-contract.json)

## Implemented

Components return their own runtime-neutral `CapabilityProvider` and declare
versioned functions in their existing core descriptor. No central function
library is edited to add a provider. Core forward-declares the interface and
retains no interpreter dependency. The registry validates provider/metadata
agreement before hardware startup; descriptor JSON generates capability
metadata directly from this same source.

The immutable borrowed catalog binds once, validates complete capacity and
ownership before publishing, and orders bindings by namespace/function. It
holds at most eight providers and 32 functions across 64 registry components;
each component declares at most eight functions with eight numeric arguments
and zero or one numeric result. Namespace versions, identifiers, UTF-8 roles
and declared callback time bounds are validated. Shared provider instances and
cross-component namespaces are refused.

Invocation checks availability, cancellation, signature and raw value widths.
Recursive dispatch fails explicitly. A fixed result scratch preserves output
on callback failure, cancellation or malformed results. `CallContext` exposes
checked UTF-8 copies and cancellation without native pointers, engine handles
or guest invocation. It and the catalog are noncopyable; all borrowed addresses
remain valid through runtime teardown. Trusted providers must validate inputs
before effects and coordinate admission with their component's lifecycle.

Existing numeric service behavior and public control paths are preserved.
Components without capabilities retain their existing descriptor JSON shape.
The descriptor writer also escapes JSON control characters in descriptions.
No guest import has been enabled by this checkpoint.

No persisted settings or packet migration is introduced. Reverting this
checkpoint restores the prior provider-free API as one unit; existing stored
modules and settings retain their format.

## Qualification

Tests were written before implementation and first failed with unresolved
provider/descriptor implementation symbols. The ten new cases cover independent
owners, bad versions/types/roles, missing providers, all numeric bit patterns,
void results, capacity/atomic registration, suspend/resume/stop, cancellation,
recursion, malformed results, checked text and generated/escaped manifests.
All **24 host suites passed** with strict warnings, exceptions and RTTI disabled.

The XIAO C6 native qualifier registers two independent synthetic components and
uses the actual service/WAMR adapter, production 80 KiB pool, 4 KiB VM stack and
8 KiB native worker. Host-driven provider calls copy real guest Unicode memory;
guest byte loads observe those writes. This qualifies portable dispatch rather
than an interpreter import trampoline.

## Compatibility and cost

Seven production profiles built with WASM, ESP-NOW/fleet, Art-Net and DDP;
Ball retains BLE. All images fit their existing app partitions. Symbol checks
verify the metadata validator is linked and the unused catalog is discarded.
These production images were built, not flashed in this trial.

New providers inherit their component's resource, cost and disable declarations;
their additional cost must be recorded when they are integrated.
