# Work package 6.2: Runtime-neutral WASM service

- Date: 2026-10-07
- Result: service and WAMR adapter implemented and qualified; production integration open
- Contract: [ADR-0009](../adr/0009-wasm-service-boundary.md)
- Evidence: [three actual-service trials](../evidence/wasm/2026-10-07-service-lifecycle.json)

## Implemented

`Runtime` exposes typed numeric values, bounded signatures, lifecycle, invocation,
cancellation and owned diagnostics without engine handles or headers. `Service`
owns the lifecycle/policy boundary and copies module input into supplied fixed
scratch. It rejects invalid calls before invocation and faults an instance after
a trap/cancellation until reload. Host tests exercise the same client against
interchangeable backend behaviors, caller lifetime, reload/generation handling,
signature limits, failure cleanup and backend contract violations.

The actual WAMR 2.4.5 adapter uses a fixed pool, one-page memory cap, software
bounds checks and instruction metering. Its internal thread manager supports
asynchronous termination on loop backedges; guest threading/WASI/AOT/JIT remain
disabled. Global runtime ownership is exclusive. The active-instance mutex is
not held while guest code runs, allowing a supervisor to cancel it safely.
Start sections and automatic constructor exports are rejected before unbudgeted
guest execution. Capability imports remain unavailable until their provider
boundary exists. A nonzero wall-clock deadline is refused until the production
deadline supervisor is implemented.

## Validation

All **22 host test executables passed**. The
[standalone qualifier](../../../v2/qualification/wasm-service/README.md) then
linked this service/adapter on XIAO C6, M5Dial S3 and HUZZAH32 ESP32. Each final
trial passed **390 checks with zero failures**, including mixed numeric and
multiple return values, memory initialization/growth, request rejection,
unreachable/OOB/divide/recursive-stack traps, fuel exhaustion, active cancellation
and recovery through reload. Automatic-entry/import/oversized-memory modules
were rejected, followed by a successful valid load/call.

Each board performed **100 load/unload cycles and 20 full start/stop cycles**.
SDK heap after warmup remained exactly constant and the unloaded pool's used
bytes remained zero. This demonstrates a non-growing lifecycle for these inputs,
not every possible guest/provider. It does not establish release of all global
SDK mutex allocations when the long-lived adapter object is destroyed.

| Board | App bytes | Peak used pool bytes | Native stack headroom bytes | Maximum trap duration us | Active cancellation us |
| --- | ---: | ---: | ---: | ---: | ---: |
| XIAO C6 | 231,600 | 72,176 | 13,708 | 4,647 | 5,823 |
| M5Dial S3 | 240,224 | 72,176 | 13,148 | 3,655 | 5,382 |
| HUZZAH32 ESP32 | 225,376 | 72,176 | 13,364 | 4,493 | 6,070 |

These app sizes include the standalone test harness and core diagnostics; they
are not deltas against a production profile. Every trial reserves a **96 KiB
engine pool**, **16 KiB module scratch**, **4 KiB Wasm stack inside the pool**,
and **16 KiB native worker stack**. Peak used pool and reserved pool are separate
costs. The priority-5 test supervisor requests cancellation after 5 ms; measured
completion includes supervisor scheduling and termination. It is not an
arbitrary-guest wall-clock guarantee.

The evidence collector validates three distinct families, complete output,
constant heap, unchanged runtime checkout, source/fixture hashes and each
image/ELF/map/config hash before writing the aggregate. Recreate it with paired
`--report`/`--build` arguments to
`v2/tools/wasm/collect_service_evidence.py`. The qualified source snapshot SHA-256
is `5886c00ee76c2609919ed46d85f0acc6a4b3727e11b9772a49c69d40e04e3f1e`.

The first development trial exposed a too-low qualifier supervisor priority;
its loop test starved that supervisor and failed. The qualifier now explicitly
sets the supervisor above the worker. The aggregate contains the subsequent
three passing runs, not the failed development trial.

## Remaining production work

This component is not yet enabled/registered in the firmware entry point.
Declared boot RAM/task costs, the bounded request queue and wall-clock/token
supervisor must be integrated before running scripts alongside actual LED,
control, radio and settings tasks. Those coexistence/fault injections are Gate D.
Seven-board production feature/profile compatibility, provider/string ABI,
registry-backed declarations and generated SDK remain open. Physical Gate C
qualification also remains open.

At the user's instruction, the three boards retain the standalone test images;
no previous-firmware restoration was requested for these final trials. Other
boards were not flashed. PC Wi-Fi was not changed and Internet remained available.
