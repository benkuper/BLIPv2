# Work package 1.1: ESP-IDF/C++20 bootstrap

## Scope

This work package creates the minimal firmware composition root and its build
contract. It deliberately contains no component registry, resource management,
transport, storage, LED, radio, or other production subsystem. Those remain
behind their dependency-map work packages.

## Compatibility disposition

- **Preserved:** V1 remains untouched, and no public OSC, settings, file, serial,
  ESP-NOW, or playback behavior changes.
- **Changed:** none; the bootstrap only emits the new diagnostic serial log marker
  `BLIP_V2_BOOTSTRAP_READY`.
- **Removed:** none.

## Locked build contract

| Item | Lock |
| --- | --- |
| ESP-IDF | `v6.0.2`, commit `7101770dc6db2667b3c477cc31365dd1acd6db4e` |
| CI image | `espressif/idf:v6.0.2@sha256:0d8c9773d48a327233f9c1d7c654ff0bcf133ae24503ea2e97a57cfe02b8cb67` |
| C++ dialect for BLIP-owned sources | GNU C++20 |
| Exceptions / RTTI | disabled in Kconfig and BLIP-owned compile flags |
| Warnings | `-Wall -Wextra -Werror` for BLIP-owned sources |
| Formatter | clang-format 18.1.8 |
| Targets | `esp32`, `esp32s3`, `esp32c6` |

The machine-readable source of this information is
[`toolchain.lock.json`](../../../v2/firmware/toolchain.lock.json). ESP-IDF
Component Manager locks are target-specific because its resolution contract
includes the target.

## Validation

Static checks, available without ESP-IDF, are:

```powershell
python v2/tests/host/validate_foundation.py
python v2/tests/host/validate_bootstrap.py
```

The CI matrix performs two clean builds per target, validates the generated
`sdkconfig` and the `main.cpp` compile command, compares the two application
images byte-for-byte, checks that dependency resolution did not change the
committed lock, and reports image size.

Hardware boot evidence is not claimed by this work package. Gate A remains
open until work packages 1.2 through 1.5 are complete and all physical-board
requirements in the quality gates have evidence.

## Rollback and migration

Rollback is removal of the bootstrap commit or continued use of the Milestone 0
planning tree. There is no persisted state, partition migration, wire protocol,
or V1 firmware change to reverse.
