# Work package 4.7: streaming and playback

`StreamLayer` copies validated RGB/RGBA and 8/16-bit updates into caller-owned
memory, rejects stale wrap-aware sequence numbers, and supports deterministic
clear-on-timeout. Network I/O remains outside the render task.

On Creators Ball V2, the live worker composites a 36-pixel stream surface,
accepts bounded updates from the DDP UDP task, and sends a clearing frame after
one second without updates. A serial `stream_pixel` action provides a focused
hardware probe. A 30-second, 30 fps run is recorded in
`docs/v2/evidence/board-bringup/2026-09-30-creators-ball-ddp.json`.
The native RMT outputs now consume the same bounded stream layer for their
configured WS2812/SK6812 pixel count. Five connected board builds received DDP
and submitted output frames during short shared-Wi-Fi HIL runs; details and the
unavailable M5StickC are recorded in
`docs/v2/evidence/board-bringup/2026-10-01-ddp-six-board-rollout.json`.
Playback is still host-only.

V2 playback uses a 32-byte versioned header, exact length, RGBA16 frames, and
separate header/data CRC32 values. `PlaybackReader` never allocates and rejects
partial or corrupt files. `PlaybackClock` provides play, pause, resume, stop,
seek, and loop behavior. V1 playback import is no longer required.
