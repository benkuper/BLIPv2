# Device identity and editable names

- Date: 2026-10-09
- Status: implemented; seven-board milestone qualification remains open
- Requirement: [device interface requirements](3.7-device-web-and-self-update.md)
- Evidence: [six-board development identity trials](../evidence/web/2026-10-09-device-identity.json)

`blip.device.identity` publishes a read-only board `type` and a persisted, editable
`name`, defaulting to that type. Names contain 1–63 bytes of valid UTF-8 without
controls or leading/trailing spaces. Saves use the shared versioned two-slot NVS
service; a failed save preserves the live identity. Reads use owned snapshots.

Both web modes display name and type with a name editor in the header. Advanced
also exposes the component in System. Polling reflects other transports' changes.
OSCQuery host information and UDP/WebSocket discovery use the same identity.
mDNS derives a lowercase DNS-safe name plus the full stable MAC suffix, e.g.
`creators-club-30aea4f3a388.local`. Non-ASCII/punctuation runs become separators;
an all-non-ASCII name uses `blip` as its hostname stem while preserving its display
name. Renaming updates the existing responder without rebooting or reconnecting.

## Hardware checkpoint

The identity HIL checks flashed MAC, serial/HTTP identity, both mDNS services,
live rename, invalid names, read-only type, and reboot persistence, then restores
the original name. These are checkpoints, not milestone completion.

| Device | Port at test | Identity checks |
| --- | --- | --- |
| Creators Ball V2 | COM10 | 19 passed |
| HUZZAH32 | COM5 | 19 passed |
| M5 Dial | COM9 | 19 passed |
| Creators Club | COM15 | 19 passed |
| XIAO C6 | COM13 | 19 passed on repeat after recovery |
| M5 Stick C | COM12 | 19 passed; ROM flashing recovered stub failure |
| Creators Tab | COM14 | Unqualified: ROM/stub flash ID `ffffff`; boot reports `flash read err, 1000` |

Full source/artifact hashes and logs are in `build/m40-identity-*-hil.json`.
XIAO's first reset trial missed serial/LAN readiness; another stub-assisted run
recovered it. Its repeated trial passed and restored `XIAO C6`. Reset reliability
still needs this recovery limitation considered during wider qualification.

HUZZAH32 passed 16 desktop/mobile browser checks with UI 0.3.1, including name
editing in Simple and Advanced. Later UI 0.3.2 serializes initial JSON responses
after Ball browser trials reproduced network-memory exhaustion. The C6 profile
also bounds receive windows and out-of-order queues; download scratch reuses its
identity-prefix buffer. An initial native web download committed the bundle
but overflowed its original 4 KiB worker stack. The worker now requests 6 KiB;
the bounded-download repeat passed ten checks, installed without a reboot, and
retained 2,036 bytes of stack headroom. Ball then passed 19 desktop/mobile browser
checks, including name edits and dynamic script publication/retirement, against
the installed UI (0.3.2 assets packaged with test bundle code 3003).
Simultaneous browser/update traffic and firmware OTA still require qualification.

The Club startup trial exposed insufficient contiguous IRAM for its 64 KiB WASM
arena. Unused MMC/NOR providers are now optional; original-ESP32 WASM profiles keep
SPI interrupts in flash. Their buses already use ordinary interrupt flags, which
defer completion during flash writes. The corrected Club image passed identity HIL
with WASM startup enabled; lighting/update coexistence needs separate qualification.

Root `AGENTS.md` requires every milestone to pass hardware validation on all seven
boards. The Tab's flash access failure prevents closing that gate.
