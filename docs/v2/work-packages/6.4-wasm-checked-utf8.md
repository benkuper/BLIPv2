## Implemented boundary

String ABI version 1 is two unsigned Wasm i32 values: default-memory byte offset
and byte length. It accepts exact UTF-8 bytes, including embedded U+0000, and
never scans for or appends a terminator. Copies are limited to 256 bytes.
Provider/identifier rules may impose smaller limits or reject embedded NUL.

`GuestMemory` supplies runtime-neutral checked copies. The WAMR adapter queries
the current memory instance and extent for each access, checks the whole range
with subtraction and retains the native base pointer only within the copy.
No engine handle or native guest pointer escapes the adapter. Empty spans
require an existing memory and an offset at or before its end. Memory growth
and zero-page instances use their actual current extents.

`read_utf8` copies through a fixed 256-byte scratch buffer, validates UTF-8,
then copies to the caller. Failure returns zero bytes and preserves output.
`write_utf8` validates the full input before checked writing. Invalid encoding,
length or memory range leaves guest bytes unchanged. Both reject overlong forms,
truncation, invalid continuation/lead bytes, surrogates and values above U+10FFFF.

Service methods additionally require a runnable module and its captured current
generation. Old spans cannot read or write a replacement module. Rejected
copies do not run guest code, change its runnable state or allocate heap. APIs
are worker-confined, including future capability-provider callbacks.

## Qualification

The new host tests were added before implementation. They cover every valid
Unicode scalar, malformed sequences, exact byte preservation, empty/end/long
ranges, unsigned overflow, short output and failed-copy atomicity. Service tests
add stale-generation and stopped/ready/faulted lifecycle checks. All **23 host
tests passed** with strict warnings and exceptions/RTTI disabled.

| Board / family | Native checks | Reload cycles | Pool peak | Worker headroom | Maximum read / write | Warmed SDK DRAM |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| HUZZAH32 / ESP32 | 1,023 | 100 | 73,640 B | 4,920 B | 283 / 53 us | 267,108 B |
| M5Dial / S3 | 1,023 | 100 | 73,648 B | 4,796 B | 96 / 20 us | 283,368 B |
| XIAO / C6 | 1,023 | 100 | 73,648 B | 5,092 B | 77 / 21 us | 363,504 B |

All **3,069 native checks passed**. Guest functions return real pointer/length
pairs for ASCII, multibyte text, embedded NUL, malformed strings and the final
memory byte. Host writes are visible to guest loads. Tests also cover absent,
zero and grown memory, reload initialization, stale spans, unaligned ESP32 IRAM
copies and cross-boundary write atomicity. Each family retains identical warmed
SDK heap across its one hundred reload/copy/unload cycles; unloaded pool use is
zero. The collector verifies physical MAC/chip identity, fixture/runtime pin,
source and artifact hashes, heap/pool/stack limits and completed build logs.

All images fit their existing app partitions. Symbol inspection verifies the
checked memory adapter is linked in every profile. The string helpers are
currently removed by linker garbage collection until bindings call them; the
full string path is exercised in the native qualifier. Deltas include the
memory adapter/vtable and build metadata. The interface adds no persistent
string buffer, heap reservation, peripheral, GPIO or radio requirement. Reads
use 256 bytes of the existing worker stack. UTF-8 service calls apply to a
loaded module and do not require reboot.
