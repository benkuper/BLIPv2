# 5.3 Dynamic frequency scaling and pixel-frame lock

All six board profiles now enable ESP-IDF power management. The
`blip.power.manager` registry component configures 80 MHz idle CPU frequency and
the board build's 160 MHz maximum. Automatic light sleep remains disabled;
the HUZZAH32 manual timer-bounded actions are still available. The component
creates a CPU-maximum lock used by the pixel worker from frame preparation
through transmission completion. The lock is released before the worker waits
for another frame. ESP-IDF 6.0.2 also manages its own SPI and RMT transfer
locks when `CONFIG_PM_ENABLE` is set.

Registry parameters expose the configured frequencies, automatic sleep policy,
active and cumulative frame locks, and lock-release errors. The manager starts
before Wi-Fi and LED services; the LED component requires its `power.cpu`
service, so registry shutdown stops pixel work before deleting the lock.
Existing generated `sdkconfig` files must be updated to
`CONFIG_PM_ENABLE=y` when reusing an older build directory; new directories
take this from `v2/firmware/sdkconfig.defaults`.

The HUZZAH32 RMT and Creators Ball V2 SPI-DMA HIL checks changed one pixel color
and restored it. Both recorded two additional applied frames, two CPU-lock
acquisitions, zero active locks afterward, zero release errors, no new failed
frames, and Wi-Fi still connected. HUZZAH32's manual light and deep sleep tests
also passed with PM enabled. M5Dial booted and reported the policy with its
pixel output left disabled. All six builds are recorded in
`docs/v2/evidence/board-bringup/2026-10-01-pm-six-board.json`.
The Ball also accepted 741 packets from each of Art-Net, DDP, and E1.31 during
a bounded shared-network soak, with no packet rejections or failed LED frames.

This does not establish a current reduction or a measured CPU-frequency trace.
Other consumers still need explicit locks where their timing requires one, and
automatic idle light sleep needs coordinated radio, USB, and board power-latch
behavior before it can be enabled. Electrical idle/sleep measurements remain
open for every board profile.
