# Work package 1.4: resource broker

## Scope

`blip_resources` provides fixed-capacity inventories, deterministic allocation,
move-only RAII leases, weak generation tokens, and atomic batch acquisition.
Claims support exclusive, shared-read, bus-member, and multiplexed modes;
capability masks, capacity, reservations, feature dependencies, and radio
coexistence participate in selection.

Build-time profile manifests use a versioned JSON schema and an offline
validator. Conflict diagnostics identify both claimants. Runtime acquisition
uses the same ownership rules and rolls back every lease if a batch cannot be
completed.

## Acceptance evidence

Host tests cover exclusive conflict, shared-read compatibility, deterministic
candidate choice, reservation and feature constraints, batch rollback, stale
lease invalidation, capacity accounting, and radio coexistence. Manifest tests
accept the minimal/valid profiles and reject committed exclusive and reserved
resource conflicts with both owner names in the diagnostic.

## Compatibility, rollback, and migration

No V1 pins, drivers, or board defaults are changed. The included minimal feature
manifest makes no hardware claim. Removing the V2 broker and manifest files
rolls back the package; there is no persisted-state migration.
