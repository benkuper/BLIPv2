# Native updates and first-run installation checkpoint

- Date: 2026-10-09
- Status: implemented; milestone qualification remains open
- Requirements: [web and self-update scope](3.7-device-web-and-self-update.md)
- Evidence: [installation and update trials](../evidence/web/2026-10-09-update-installation.json)

The device checks a public JSON catalog and independently installs firmware or
web assets without a browser. Settings retain endpoint, channel, check interval
and separate automatic policies. Standard builds use HTTP without credentials,
signing or TLS; HTTPS is an optional build. Downloads enforce declared bounds,
SHA-256, device/profile/layout identity, A/B firmware confirmation and atomic web
replacement. The local simulator and publisher implement the deployable server
contract; putting that service online remains the user's later deployment step.

Normal factory flashing writes the full web bundle into a separate filesystem
image. `BLIP_FLASH_WEB_UI=OFF` writes an empty filesystem instead. Both builds
produced the identical HUZZAH32 application SHA-256
`868f354f581c0d8008d28dd497c7152dc85589bf92c8fd17d71d0d2f86836dfe`.
Only the small first-run page remains in the application. With no full interface,
that page requests the matching online bundle and refreshes automatically; it
also exposes Wi-Fi setup and retry. Installed files use the automatic media
service, so later firmware updates preserve the interface independently.

The browser's manual-upload checksum now also works on ordinary device HTTP
origins, where SubtleCrypto is unavailable. The dependency-free fallback processes
the existing image buffer, uses bounded scratch space and yields every 64 KiB.
Known SHA-256 vectors, padding boundaries and firmware-sized data agree with the
host's independent crypto implementation. Manual uploads now inspect BLIPREL1
identity before opening the inactive app slot, including board, target, chip
header, layout, flash capacity, profile, features and API. Reinstalling a matching
release remains possible without a website catalog.

## Hardware checkpoint

HUZZAH32 on COM5, MAC `30:ae:a4:f2:d1:84`, passed:

- 16 empty-filesystem/browser checks: automatic UI download, refresh without a
  reboot, real HTTP-origin checksum, browser firmware upload, boot confirmation
  and retained UI.
- 12 native firmware-update checks: website release code 1 to 2, exactly one
  software reboot, boot confirmation, preserved name/UI and HTTP release status.
- 23 checks on the newer image: eleven incompatible/incomplete manual prefixes
  rejected, valid full browser upload accepted, boot confirmed and UI retained.

The UI in these trials was 0.3.4, code 3004, 26,313 bytes. The earlier Ball native
web download and storage trials remain documented in the identity/media records.
All seven current profiles compile with manual identity validation. Host checks
passed 33 suites, browser-module checks passed 31 tests and release-server checks
passed nine tests. Original update settings were restored after the trials; the
validated code-2 firmware and downloaded UI remain installed. PC Wi-Fi was never
changed.

These focused trials do not close the milestone. Required remaining work includes
six-board hardware regression, interruption/cancellation/corruption recovery on
all three chip families, updates during lighting/browser/BLE/fleet traffic,
first-run recovery after failed downloads, and broader external-media/application
consumer integration. Creators Tab was removed from all checks at the user's
request on 2026-10-09. No physical measurements or endurance gate is implied by these
results.
