# Work package 6.6: Owned script control store

- Date: 2026-10-08
- Status: Store/runtime query qualified; production script integration pending
- Contract: [ADR-0016](../adr/0016-wasm-owned-script-controls.md)
- Evidence: [owned script store](../evidence/wasm/2026-10-08-script-control-store.json)

## Changes

The WASM library now contains `ScriptControlStore`: owned declarations, typed
parameter values, copied action/event FIFOs and an invocation-scoped event
builder. Immediate atomic admission protects value/queue operations. Generation
leases preserve retired metadata until the last reader releases; replacement
refuses a live lease. Retirement rejects new work, preserves action IDs for
cancellation completion, and filters stale events. Publication checks reserved
IDs, exact action callback signatures, and the fixed guest arena for string
arguments. Read-only/write-only access applies to external control, with separate
owner access for guest status/settings. Type, bounds and UTF-8 remain enforced.

The WAMR adapter adds a passive immutable-i32-global query. It rejects missing,
mutable, wrongly typed and unloaded globals, preserving unsigned i32 bits without
returning an engine pointer. String actions declare their 512-byte guest arena
through `blip_controls_buffer_v1`; the future production worker will copy fields
through the existing checked-memory API before its supervised callback.

The store is **not instantiated or linked into production firmware yet**. All
seven production images do link the passive WAMR query. Their static RAM remains
unchanged; the future worker owner must explicitly account for the store and
message scratch outside its 8 KiB stack.

## Verification

The six shared cases began with an unimplemented API/link failure. All **27 host
suites pass**. Store cases cover overwritten upload/input strings, NUL/UTF-8 and
capacity, scalar access/type/bounds, copied four-message queues, retained stale
action IDs, callback signature/arena/collision rejection, complete event fields,
builder abandonment and a real thread retaining metadata across retirement.

The independent ESP-IDF qualifier compiles those exact cases on three chip
families. Each runs the six cases 21 times and **32 real-engine checks**. The
engine checks execute a callback with boolean, full-width signed integer, number
and copied NUL-containing string fields, repeat 20 load/call/unload cycles and
reject invalid exported globals/arenas. All **474 case/check passes** succeeded,
with flat warmed heap in both repeat phases:

| Board | Shared repeat heap | Engine repeat heap | Qualification stack headroom |
| --- | ---: | ---: | ---: |
| XIAO C6 | 318,384 B | 317,936 B | 8,336 B |
| HUZZAH32 | 140,240 B | 139,792 B | 8,224 B |
| M5Dial S3 | 239,320 B | 238,872 B | 8,120 B |

On all three targets the store is **11,792 bytes**, a queued message **664 bytes**
and an owned value **144 bytes**. The largest store compiler frame is 224 bytes
on C6 and 208 bytes on ESP32/S3. These are individual frames, not a whole-call
stack guarantee. The qualifier's 24 KiB stack accommodates local allocating test
fixtures; it is not the production worker stack. Its WAMR pool peaks at 71,072 B
within a separate 98,304 B reservation, which is also distinct from production's
80 KiB pool/ESP32 IRAM policy.

An initial C6 test hung because a higher-priority reader used `sched_yield`, which
did not admit its lower-priority owner on one core. The fixture now sleeps while
waiting and has an independent higher-priority supervisor. Heap samples allow
the idle task to reclaim joined reader task storage. The final full image passes.
This was a test scheduling failure, not evidence of production concurrency
qualification. Matching bootloaders/partitions/apps were flashed; M5Dial used
stub-assisted `run`. These validated qualifier images remain installed.

## Next integration and remaining scope

Reserve the store in `EspWasmComponent`, prepare before engine load and publish
only after callback/arena validation. Retire on unload, replacement, fault and
stop, and include metadata lease quiescence in component teardown. Implement
guest parameter/event imports and expose the store through the existing dynamic
schema/value hooks.

Use the worker's existing ordered request queue to carry script-action markers
and captured budgets, while the store owns copied fields. Preserve global request
ID ordering and complete every admitted action on cancellation. Independently
merging two action queues could violate the completion ring's current FIFO
assumptions. Close script admission when replacement/unload is accepted so later
old-generation actions cannot be queued behind their replacement. Failed commit
must hide the new schema and unload its module; metadata contention must produce
an explicit bounded failure.

Deliver copied typed events through a core-owned interface, carry generation
tokens through external transports, implement lossless i64 encoding and automatic
web schema refresh, then exercise real controls in a browser and simultaneous
production queries/reloads. Bindings/examples and remaining script LED work follow
in 6.7. Full Gate C/D, physical/RF/soak tests and milestones 7–9 remain open.
Neither work package 6.6 nor the full implementation plan is complete.

## Compact text reservation checkpoint

The store now packs queued scalar metadata and reserves string storage from the
accepted schema. The four action slots, four event slots, four fields per
message, 128-byte string limit and 16 control limit are unchanged. Numeric-only
or empty schemas reserve no text; the production live-controls fixture reserves
640 bytes; the maximum schema can reserve 6,144 bytes. Owned messages still copy
every field and preserve i64/f64 bits. No transport callback allocates text.
Component resource accounting includes the maximum dynamic reservation.

The worker frees retired text only after metadata leases and accepted queued
actions drain. A copied owned message survives that release. Replacing a schema
resizes the reservation before publication. The store's fixed size is now
5,664 bytes on C6, ESP32 and S3, compared with 11,808 bytes immediately before
this change. The older 11,792-byte measurement above belongs to its earlier
checkpoint.

The shared suite adds a full-capacity case covering all action/event slots,
maximum strings, wraparound, source overwrite, mixed scalar bits, independent
parameter text and safe retirement. The standalone qualifier passed 168 shared
case runs and 32 actual engine checks on XIAO, HUZZAH32 and M5Dial, including 20
replacement cycles with no settled heap variation. Its separate test stack and
pool still differ from production. The production checker also verifies a
640-byte reservation while loaded and zero after retired leases drain.

Exact report and artifact hashes are included in
[the worker/RAM evidence](../evidence/web/2026-10-09-reserved-update-worker.json).
This is a RAM and ownership checkpoint; guest events, remaining transport/SDK
integration, M5StickC burst loss, seven-board qualification and the full plan
remain open.
