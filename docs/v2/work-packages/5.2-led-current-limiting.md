# 5.2 Calculated LED current limiting

The strip output now limits encoded channel bytes immediately before SPI-DMA
or RMT submission. Its model counts 1 mA idle per pixel and 20 mA at full
code per RGB(W) channel. The estimator rounds up aggregate channel current.
The limiter reduces channel codes with floor rounding so the calculated
result cannot exceed the configured budget, drops the scale immediately on
overload, and raises it gradually after load falls. Start/end framing and
clocked-strip brightness headers are left intact.

`blip.output.strip0.power_budget_ma` is persisted with strip settings. Its
default is 1500 mA; the current hard configuration ceiling is 5000 mA. A
budget below the modeled idle current is rejected. The registry also exposes
`estimated_current_ma` and `power_scale_q16`. V2 strip settings format 1 is
read with the default budget and re-saved as format 2 on the next change.

The host suite tests one-wire and clocked byte layouts, unequal channel
weights, budget enforcement, smoothing, invalid settings, and format 1
migration. All 18 host tests pass. All six board builds pass, recorded in
`docs/v2/evidence/board-bringup/2026-10-01-led-power-six-board-builds.json`.
The Ball SPI-DMA and HUZZAH32 RMT serial checks are in
`2026-10-01-ball-power-limit.json` and
`2026-10-01-huzzah32-power-limit.json` in the same evidence directory. Both
checks observed a capped estimate, reduced scale, zero output failures, and
restored their prior settings.

This is an electrical-current **model**, not a measurement. Pixel idle and
channel currents, power supply limits, and the Ball's battery rail must be
calibrated before the 5000 mA ceiling can be treated as a board safety rating.
External current measurement and Gate C waveform qualification remain open.
